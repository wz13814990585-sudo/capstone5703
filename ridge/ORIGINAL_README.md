# Ridge因子对照实验说明

## 一、项目目的

本文件夹用于比较不同因子组合和不同训练机制下的Ridge表现，说明结构与小组XGBoost README保持一致。

采用两种训练机制：

1. 滚动窗口训练（Rolling Window）：最近3年，每4周重新训练。
2. 固定阶段训练（Fixed Training）：每个阶段开始时，用当时可用的全部历史数据训练，阶段内不更新模型。

每种机制分别测试7个筛选因子、7＋4个宏观因子、全部45个因子，共6组。本版已对齐XGBoost的Development筛选门槛、选参目标、固定阶段训练机制和指标公式。Ridge保留自身的alpha网格和标准化。

**本次6组均完成Development筛选，其中5组通过并完成Validation和Final Test；滚动45因子未通过，不强行生成测试成绩。** 这是筛选结果，不是程序未完成。

滚动频率按小组确定的每4周执行。队友提供的XGBoost代码目前按自然月分组，尚需队友同步修改；本交付不修改队友代码，也不宣称三种模型的实际样本和训练日期已全部统一。

## 二、文件和运行方法

本文件夹只需交付两份文件：

- `README.md`：实验规则、运行方法和本次结果。
- `train_ridge_comparison.py`：独立运行程序，不依赖旧core脚本或队友代码。

另需小组共享的CSV：`test_45_factors_weekly(1).csv`。把CSV与程序放在同一文件夹，在该文件夹打开终端。若CSV实际名称不同，替换命令中的文件名即可，也支持带引号的完整路径。

建议Python 3.12，安装本次实际验证的依赖版本：

```bat
python -m pip install numpy==2.3.5 pandas==3.0.1
```

运行全部6组：

```bat
python train_ridge_comparison.py --input "test_45_factors_weekly(1).csv" --mode both
```

只运行滚动版：

```bat
python train_ridge_comparison.py --input "test_45_factors_weekly(1).csv" --mode rolling --output "results_rolling"
```

只运行固定阶段版：

```bat
python train_ridge_comparison.py --input "test_45_factors_weekly(1).csv" --mode fixed --output "results_fixed"
```

查看帮助：

```bat
python train_ridge_comparison.py --help
```

本程序没有 `--check-only` 参数，输入核验会在训练前执行。默认输出到程序旁的 `ridge_results_aligned`。输出目录须不存在或为空；再次运行请换一个 `--output`，不会覆盖已有结果。不要使用 `python -O`，需要保留核验断言。

程序不修改CSV，不抓取网络数据，不需要API密钥。用NumPy求解带L2惩罚、截距不惩罚的Ridge，不需要安装scikit-learn或XGBoost。

主要输出：

- `selection_status.csv`：全部6组的通过状态和选定alpha。
- `final_test_comparison.csv`：最终对照；未通过组保留状态，指标为空，不填零。
- `all_stage_metrics.csv`：已选中模型的各阶段指标。
- 各模式下的 `predictions.csv`：逐周逐股票预测，含date、ticker、label_end_date、target、stage、fold_id、model、mode、alpha、fit_date、prediction，可交给回测同学。
- `development_alpha_scores.csv`、`locked_selection.json`：候选评分、门槛和选参记录。
- `weekly_metrics.csv`：Top5名单、组合收益、基准收益和逐周指标。
- `folds.csv`、`model_parameters.csv`：训练样本范围、模型系数及预处理参数。
- `config.json`、`verification.json`、`excluded_rows.csv`：规则和核验记录。
- 根目录 `run_manifest.json`：所有请求实验处理结束后生成，记录输入/程序哈希、版本和组别状态。`completed`表示流程完成，不代表所有因子组都通过筛选。


## 五、超参数筛选方法

每种训练机制、每组因子独立测试6个Ridge正则强度：

```text
alpha：0.01、0.1、1、10、100、1000
```

统一的Development通过条件：

```text
Mean Rank IC > 0
Rank ICIR >= 0.05（未年化）
正Rank IC周占比 >= 50%
```

通过三项门槛后，选择 `Top5 Excess` 最高的alpha；相同时依次比较Rank IC、Rank ICIR，均优先更高者。完全相同时保留原候选顺序。没有候选通过，则标记 `no_candidate_passed`，不运行该组Validation/Final Test，不采用兜底候选。

`Top5 Excess`按周超额收益序列复利年化，不再使用“策略年化减基准年化”作为选参目标。Validation和Final Test不再调alpha。

**阶段边界保护：** alpha在2024-09-01锁定，参与选参的标签实现日必须严格早于该日期。因此信号为2024-08-30、但收益要到2024-09-06才实现的最后一周，不参与选参。Development展示仍包含完整261周，选参使用前260周；两者不要混淆。

这项保护比队友当前XGBoost代码直接使用全部Development信号更严格，需要队友同步处理才能达到完全相同的选参样本。Development成绩参与了参数选择，本身不是独立验证成绩。

| 模式 | 7因子 | 7＋4宏观 | 45因子 |
|---|---:|---:|---|
| 滚动 | alpha=1000 | alpha=1000 | 6个候选均未通过 |
| 固定阶段 | alpha=100 | alpha=100 | alpha=100 |

预处理只在当前训练样本上拟合：中位数填补、1%/99%缩尾、均值/标准差标准化。本次输入没有缺失，不触发填补；换入缺失数据会在输入核验时报错。Ridge保留标准化，这是模型需要，不要求树模型也做。

## 六、滚动窗口训练

使用最近3个日历年的历史，每4周（小组口头称“每月”）重训一次，连续4周节奏跨阶段不重置。

```text
拟合日前最近3年训练 → 接下来4个周度快照使用同一模型
向前移动4周 → 再取最近3年重训
Validation与Final Test继续滚动，但alpha不再改变
```

第一拟合日2019-09-06。每周用当周X预测下一周收益，不提前读取未来4周X，也不是预测4周累计收益。训练标签实现日必须严格早于拟合日，与XGBoost的严格小于规则一致。

程序不按自然月边界分组。队友现有XGBoost脚本按自然月，RF脚本按每周，需他们按共同约定同步修改，不能把口头一致写成代码已经一致。

## 七、固定阶段训练

本版已取消旧版“最初训练一次后全程冻结”的实现，改为：

```text
2019-09-01：使用此前可用历史（约3年）训练，预测Development
2024-09-01：使用此前全部可用历史（约8年）重训，预测Validation
2025-09-01：使用此前全部可用历史（约9年）重训，预测Final Test
```

各阶段内系数和预处理参数固定，但每周输入X更新。使用同一Development选定的alpha，不在验证或测试阶段重新选择超参数。训练信号日期及标签实现日均严格早于阶段开始日。

这是阶段重训，不是全程冻结，也不是每4周扩展训练的Expanding Window。与滚动版比较时，同时改变了训练频率和历史数据长度，不能把全部效果归因于单一因素。

## 十、阶段性判断

1. 滚动7因子与7＋4因子的Rank IC为正，但Top5毛收益和超额收益为负，不能仅凭排序相关为正判断盈利能力。
2. 宏观因子在本次两种训练机制下改善了Top5最终期收益，但Rank IC略有下降；这不是“所有指标均改善”，也不足以证明稳定增益。
3. 固定阶段45因子本次Top5最终期收益较高，但整体Rank IC较弱；不能据此反过来选择实验规则或宣称其稳定最优。
4. 滚动45未通过门槛是正式实验结果，不应在看过结果后降低门槛补出成绩。

代码和结果已核验：191个选定模型拟合块的训练范围、预处理、参数及预测独立重算通过；15行阶段指标按队友XGBoost的指标函数口径复算，最大差异约3.25e-15。Spearman用平均排名后的Pearson等价计算，不依赖SciPy。程序本身保留另一种Ridge求解及保存参数重建预测的检查。

原版代码和结果保留，本版不覆盖。因选参规则、训练方式及部分时间边界发生变化，新旧数字不是单纯模型性能提升对照。

## 十二、指标说明

- `IC`：每周预测与真实target的截面Pearson相关，按周等权平均。
- `Rank IC`：每周Spearman相关，按周等权平均。
- `ICIR`：周IC均值／样本标准差，未年化。
- `Rank ICIR`：周Rank IC均值／样本标准差，未年化。
- `Annualized Return`：每周预测最高5只等权；先逐股把对数收益转为exp(target)-1，再算组合周收益，以52周复利年化。
- `Information Ratio`：周超额收益均值／样本标准差 × √52，仍然年化。基准是当周可评估股票等权组合，不是SPY。
- `Top5 Excess`：先逐周计算Top5组合收益减基准收益，再复利年化，即 exp(mean(log(1＋周超额收益))×52)－1。
- `Positive Rank IC`：有效Rank IC周中，大于零的周数占比。

旧版“策略年化减基准年化”仅另存为 `legacy_excess_annualized_return_pp`，单位为百分点，不参与选参，也不能与 `Top5 Excess`混用。原始输出的相关系数、比率、收益和占比均为数值小数；README为阅读方便使用百分比。

不计手续费、滑点、换手成本和流动性限制。以收盘后因子按同一收盘价建仓的可执行性未验证，因此属于信号收益评价，不等于实际可成交收益。样本、日期和信息可用性全部统一后，才能进行严格的跨模型公平比较。
